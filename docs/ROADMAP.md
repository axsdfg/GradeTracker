# 路线图

没有承诺的交付日期。按「价值 / 成本」排序，靠上的更值得做。

---

## 近期（高价值）

### 1. 真实的等级赋分
现在的 `assignedOf()` 是线性得分率映射：`base + (max−base) × 得分率`。
真实规则是按省份的分段比例把原始分划成若干等级再赋分，各省不同（浙江 21 个等级、山东 8 个等级…）。

- 改哪里：`app/index.html` 的 `assignedOf()`，以及设置页的赋分参数区；
- 需要什么：数据结构（等级数、各等级人数比例、赋分区间）+ 各省规则表；
- 难度：中。数据比代码难。

### 2. 拆分源码但保留"无构建"
现在 3,000 行挤在一个文件里，改一处要在长文件里翻。方案：`src/` 下按职责拆成 `store.js` / `calc.js` / `render.js` / `style.css`，加一个 30 行的拼接脚本生成 `app/index.html`。

- 好处：可维护性 + 仍然产出单文件，APK 集成方式不变；
- 代价：多一步 `node scripts/build.js`，需要把 CI 改成"先构建再测"。

### 3. 真实渲染的冒烟测试
现有回归只验证逻辑（DOM 桩），不验证像素。补一个 Playwright 用例：打开页面 → 录入一场考试 → 截图首页/分析页 → 断言关键元素存在。

- 能抓到的问题：布局溢出、图表尺寸为 0、深色模式下文字不可读。

## 中期

### 4. 数据加密（可选开关）
localStorage 明文是已知短板。可以做"可选口令加密"：用户设口令 → `PBKDF2` 派生密钥 → `AES-GCM` 加密整份 JSON。

- 取舍：忘记口令 = 数据全丢；每次启动要输口令；
- 所以定位为**可选项**，默认关闭。

### 5. 桌面小组件
纯原生（Glance）。显示"距下次考试 N 天 + 最近一次总分"。需要原生侧读 localStorage 的桥，或者把数据同步一份到 SharedPreferences。

### 6. 错题拍照
需要 `CAMERA` 权限 + 图片落文件目录（只存 URI，不存 base64）。前端错题模型已经预留了位置。

### 7. 多设备同步
最省事的做法：用户自备 WebDAV / 坚果云，手动"上传/下载备份"。不做账号体系——那会毁掉"零注册"的定位。

---

## 长期 / 不确定

- **iOS 版本**：单文件 HTML 理论上可套 `WKWebView`，但 localStorage 上限与清理策略不同，需要先验证。
- **PWA 版本**：加 `manifest.json` + Service Worker 就能装机，代价是要处理版本更新与缓存失效。
- **成绩单 OCR**：从学校发的成绩单截图里自动提取分数。成本高，且是最大的隐私风险点（图片要留在本地处理）。
- **多用户（一个手机多个孩子）**：state 里加 `profiles` 维度，切换时换整份数据。

---

## 明确不做

| 不做 | 原因 |
|---|---|
| 账号 / 云同步服务 | 一旦有服务器，就要处理合规、存储、注销，还会毁掉零注册的定位 |
| 社交 / 排名榜 | 学生成绩互相比排名是有害的，这个应用只想跟自己比 |
| 广告 / 增值功能 | 定位是工具，不是产品 |
| 上传数据做"AI 分析" | 与零网络的隐私承诺直接冲突 |
